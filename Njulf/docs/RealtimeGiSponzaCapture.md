# Realtime GI Sponza capture contract

`SampleSponzaGiCaptureContract` is the single in-repo capture contract for the 2026-07-16 Sponza GI transport/support regression. It runs the canonical `GiSponzaRightWallStationary` profile at `1600x900`, locks exposure and deterministic validation settings, warms DDGI for 360 frames, captures both named endpoints, and traverses the 9 m vertical path in 16 seconds at 60 fixed frames per second. The canonical profile deliberately contains no authored DDGI volumes; Sponza exercises the generic `DdgiHigh` camera-relative rings.

The contract is intentionally receiver-centric. Its central upper façade, right upper wall, left and right gallery interiors, central arcade interior, and outdoor reference ROIs are world-space AABBs and are sent to the Simple-DDGI CPU coverage oracle at every one of the 960 fixed vertical-path frames. Each receiver must remain covered by the generic near or mid ring (at most `3.75 m` spacing), and every actual ring-edge transition must have a coarser fallback. The local-volume contributor output is expected to be empty unless a developer explicitly adds a standalone authored volume for an A/B test.

Use `--sponza-gi-capture-dir <directory>` for scripted captures. It is deliberately incompatible with smoke-frame options and baseline one-frame export because it owns its complete 1,398-frame sequence. The run emits its contract fingerprint, hash-addressed artifact index, coverage-oracle sidecar, visual-metric-gate sidecar, two performance snapshots, and thirteen locked outputs per endpoint. In addition to beauty/direct and the existing ownership/support views, schema v5 records `DdgiGatherClipmap`, `DdgiGatherBlendWeight`, `DdgiGatherFallback`, `DdgiSampledIrradiance`, `DdgiFinalDiffuse`, and `FinalIndirect`. Its direct-only output disables DDGI plus diffuse/specular environment surface lighting while retaining the sky background, so beauty-minus-direct isolates indirect transport instead of comparing against unowned diffuse IBL. It disables particles and animation, reinitializes sample particle seeds, recreates the fixed directional sun, and rejects a missing immediate screenshot service or a resolution mismatch rather than mixing output states.

The source glTF `SUN` is a disabled authoring marker. Its downward elevation is retained, while the runtime key rotates its azimuth by 180 degrees so the right-wall view contains both directly lit and occluded receivers. The startup benchmark applies the same low camera bookmark as the capture, and schema v5 fingerprints the complete directional-light profile so future scene/runtime drift fails before evidence is recorded.

For this closure, validate the transport mechanics before interpreting absolute luminance: visible support and spatial coverage should remain high, ownership/effective weight should approach `1`, fallback should remain near zero, and final/raw receiver energy should not collapse when raw energy is measurable. The simple path's historical `DataConfidence` field is normalized directional-selection support, not data validity, so values around `0.38` are plausible and must not be gated against the old `0.7` target. Sampled irradiance, effective sky visibility, and second-volume contribution remain view-dependent investigation signals rather than fabricated image-pass thresholds; the visual metric gate stays unevaluated until an approved baseline is imported.

Each endpoint output is held for three frames. The first queues the renderer-target request and presents the requested camera/debug state, the second spans the renderer's two-frame timestamp latency, and the third retains that identical state while the client-area screenshot and performance snapshot observe settled output. This is required because the game callback runs before the current Vulkan frame is submitted. `sponza-gi-capture-run.json` cannot become `completed` until every requested `.renderer.png` exists, has a structurally complete PNG stream, and has a recorded SHA-256 and byte count that remains stable across two rendered-frame observations. The capture waits for a bounded 600-frame renderer settlement interval, then writes `failed` if any request remains missing or incomplete. A screenshot request by itself is never capture evidence.

Scripted runs use `ProductionTiming`: detailed investigation counters are disabled and only the non-debug beauty endpoint is timing-eligible. `Ctrl+F11` starts `DetailedDiagnostics`, which enables the detailed GI counters, disables GPU timing collection, and labels its output as diagnostic evidence rather than production performance. Both modes write `sponza-gi-visual-metric-gate.json`; it defines deterministic world-space ROI metric requirements but is explicitly `not-evaluated-no-approved-baseline` until reviewed reference images and thresholds are imported. No visual baseline or threshold is fabricated by the harness.

Original source baseline files are tracked separately in [the baseline manifest](../Plans/Baselines/RealtimeGiClosure-20260715/manifest.json). They remain pending external import until the supplied attachment files and their SHA-256 values are available.
