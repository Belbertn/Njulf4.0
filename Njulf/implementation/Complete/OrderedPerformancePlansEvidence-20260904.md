# Ordered Performance Plans — Results

## Plan 5 — GTAO spatial optimization

- Implemented graph-owned `GtaoCurrentGeometry` (`RG32UI`) at the GTAO working extent. Raw GTAO publishes packed normal/view depth; temporal consumes it without depth reconstruction and retains history age/rejection packing.
- Spatial shared memory now loads unique source texels. Reduced-resolution taps combine exact separable Gaussian coefficients before geometry/bent-normal evaluation; full resolution uses a one-to-one fast path. Raw debug sampling is skipped outside its views. Unused Hi-Z, temporal depth, and spatial depth bindings were removed.
- Focused verification: three changed shaders compiled; targeted `spirv-val` passed; Release build passed; GTAO tests passed 9/9.
- Matched 1920x1080 Sponza/DDGI High capture (120 warmup, 60 measured): GTAO aggregate 5.91 -> 5.74 ms (-2.92%); spatial 1.43 -> 1.30 ms (-9.03%); GPU frame average 24.79 -> 24.69 ms (-0.38%), p95 25.23 -> 25.23 ms. HDR relative RMSE 0.000142, FLIP p95 0.00264 (passed). Health passed with zero validation warnings/errors.
- Cost: GTAO targets increased by 15.82 MiB at full resolution for the current-geometry scratch.

## Plan 6 — Bistro ThinGlass transparency specialization

- The Bistro production capture was fragment-bound enough to select the plan's fragment branch: 1,588 transparent meshlets accounted for a 1.31 ms transparent pass in the fresh baseline, while the renderer was already using its taskless mesh path.
- Added one missing `ThinGlass + SortedAlphaBlend + RaySceneRequired` program. ThinGlass now has its own run class; sorted non-ray reuses the existing ThinGlass artifact and weighted OIT continues to use the bounded generic artifacts, so no variant matrix was added.
- The specialized shader retains material alpha coverage, directional DDGI, shadow/reflection ray support, and the existing thin transmission/refraction result through the existing `FORWARD_THIN_GLASS_ONLY` contract.
- Focused verification: new shader compiled; production functional-atomic audit passed; targeted Vulkan 1.3 `spirv-val` passed; Release build passed; partitioning tests passed 11/11. The matched candidate exercised one 1,588-draw ThinGlass run with one bind and no universal fallback. A short standard-validation attempt reached the scene but validation policy kept hybrid ray reflection inactive, so the measured production run and SPIR-V validation are the useful checks.
- Matched 1920x1080 Bistro Presentation/DDGI High capture (120 warmup, 60 measured): transparent aggregate 1.314 -> 0.686 ms (-47.8%); GPU frame average 26.97 -> 26.51 ms (-1.69%), p95 28.41 -> 28.08 ms (-1.15%); ForwardPlus 12.20 -> 12.28 ms (+0.58%, effectively neutral). HDR relative RMSE 0.0458 and FLIP p95 0.00835 passed. Both production captures passed health; the candidate reported zero validation warnings/errors.

## Plan 7 — post-forward hybrid-reflection profiling

- Reused the warmed 1920x1080 Sponza/DDGI High capture from plan 5 because the intervening ThinGlass-only change cannot affect the opaque hybrid-reflection stack. The measured stack was 3.54 ms: DDGI base 1.55 ms, classify/compact + SSR 0.54 ms (the stable telemetry bucket intentionally combines those two graph passes), ray query 0.004 ms, resolve 0.52 ms, temporal 0.47 ms, spatial 0.33 ms, and composite 0.13 ms.
- DDGI base was the dominant subpass (44% of the stack). The adaptive frame had zero ray-query requests and all 32,400 tiles on the reuse path, so expanding every task record from 8 to 12 words would add 50% task-buffer traffic to optimize effectively no ray work.
- Per the plan's stop condition, the ray-task candidate was not implemented and no unrelated reflection change was substituted. Repeated sparse-lobe pipeline labels represent separate material/sided or accepted/fallback submissions over partitioned draw streams, not duplicate execution of the complete post-forward reflection stack.

## Plan 8 — production scene-compaction output trimming

- Reserved compaction flag bit 7 for aggregate validation output. Production flat and instance-expansion shaders now reserve and write only their material/sided buckets; CPU/GPU submission validation explicitly enables the retained aggregate stream. Global candidate, emitted, and overflow diagnostics remain unconditional, and aggregate capacity can no longer reject an otherwise valid production bucket write.
- Aggregate allocation, descriptors, readback, and comparison support remain available. Production reset and output barriers skip the aggregate buffer, while validation mode retains the prior clear/barrier contract.
- Focused verification: all eight flat/instance, virtual/resolved, and diagnostic shader variants compiled and passed targeted Vulkan 1.3 `spirv-val`; production functional-atomic audit passed; focused compaction contracts passed 12/12 and the Release application build passed.
- Matched 1920x1080 Bistro Presentation/DDGI High capture (120 warmup, 60 measured): `SceneOpaqueCompaction` 0.82 -> 0.76 ms (-7.3%), p95 0.95 -> 0.90 ms (-5.3%); GPU frame average 26.532 -> 26.556 ms (+0.09%, neutral), p95 27.981 -> 28.053 ms; ForwardPlus 12.33 -> 12.31 ms. HDR relative RMSE 0.0596 and FLIP p95 0.00571 passed. Both runs emitted 44,176 commands without overflow and passed health with zero validation warnings/errors.
- A short Cornell validation capture proved that validation still enables and fills the aggregate stream (CPU/GPU counts both 7). Its resolved-address comparison reported seven key mismatches because the CPU keys use direct meshlet indices while the GPU keys use frame-resolved virtual-table addresses; this pre-existing normalization limitation is recorded rather than treated as a regression in the new output gate. An attempted optimization-disabled comparison was stopped during cold preparation because it required a separate, expensive pipeline family.

## Plan 10 — compacted motion-vector sided raster

- Extended dynamic raster-state eligibility only to the compacted solid and masked motion-vector mesh pipelines. Each compacted draw now emits both states explicitly: one-sided partitions use back-face culling, while double-sided and unspecialized mixed partitions use no culling; all retain reverse-Z `GreaterOrEqual`. Non-compacted and foliage paths are unchanged.
- Focused motion-vector tests passed 10/10 and the Release application build completed. The production benchmark exercised both dynamic pipelines successfully, which also checks that their Vulkan pipeline state admits the emitted commands.
- Exact adjacent 1920x1080 Bistro Presentation/DDGI High comparison against the plan 8 candidate (120 warmup, 60 measured, identical 44,176 emitted commands): `MotionVectorPass` 1.088 -> 0.979 ms (-10.0%), p95 1.115 -> 1.033 ms (-7.4%). HDR passed (relative RMSE 0.0610, FLIP p95 0.00642).
- GPU frame average was 26.556 -> 27.001 ms (+1.67%) and p95 28.053 -> 29.515 ms. This was accompanied by an unrelated `HybridReflectionResolvePass` excursion from 0.550/0.557 ms average/p95 to 1.157/3.820 ms, while ForwardPlus and the other dominant passes were flat or slightly lower. Per the requested retain-and-record policy, the clear local improvement is kept and the noisy frame result is not used to revert it.
- A separate settled Sponza/DDGI High capture also reduced motion-vector time despite a larger visible stream: 0.684 -> 0.637 ms average (-6.8%) and 0.947 -> 0.884 ms p95 (-6.7%), with 22,092 rather than 17,652 emitted commands. Its whole-frame and HDR values are not treated as an A/B result because plans 6, 8, and the DDGI cache work intervened after that older baseline.

## Plan 13 — defer DDGI transport audits during camera-ring motion

- Added a submitted-frame camera-motion gate around transport-audit admission. Any active camera-following ring must remain at the same submitted camera position for four frames before a new audit may freeze; authored/static-only fields bypass the gate. Existing frozen audits are not cancelled by view motion, while camera cuts, real remaps, scene/source-boundary changes, generation changes, and loss of the live propagation boundary reset stabilization.
- Added cumulative deferred-start telemetry and the explicit `camera-ring-motion-stabilizing` reason to renderer diagnostics and the sample diagnostic report. The gate observes only successfully submitted DDGI uploads, so skipped CPU frames cannot falsely rearm an audit.
- Focused transport-motion and existing audit tests passed 10/10; the Release application build passed.
- One complete 300-frame Sponza Horizontal/DDGI High route recorded 288 deferred audit starts. `SimpleDdgiTransportAuditPass` averaged 0.238 ms with a 1.422 ms p95, versus the plan's approximately 2.14 ms recurring incident cost. GPU frame average/p95 were 33.05/41.18 ms; without a fresh pre-change capture these whole-frame numbers are recorded, not claimed as an A/B gain.
- A short stationary Sponza follow-up reached a complete, current transport certificate (12,927/12,927 participants, 62 audit chunks) and cleared the deferral reason, confirming that audit/certification rearms after stabilization. The benchmark's broader settle policy exhausted its 256-frame allowance even though the certificate was current, so that timeout is recorded rather than hidden.

## Plan 11 — meshlet tuning and Sponza sidedness audit

- Added a validated `-MeshletBuildProfile` control to `cook-bistro.ps1` for the three runtime-compatible 48-vertex/64-triangle profiles. The complete profile record now participates in the cooker settings hash, so changing any bound or clustering parameter invalidates incremental output. The 64/126 profile remains available to offline tooling but is deliberately excluded from the Bistro script because runtime content-bound plumbing is not implemented.
- Raised only the cooked local-index sequence encoder's declared alphabet from the production 48-vertex limit to the format's supported 64-vertex limit. The round-trip test now carries local index 63 through meshoptimizer compression and cooked loading. Focused identity, bounds, cone, hierarchy, and runtime-permutation checks all pass (16 relevant tests); Release AssetTool and application builds pass.
- Added a mesh-only `meshlet-profile-audit` command and ran it over both Bistro sources. Portable baseline: 85,993 LOD0 meshlets, 70.5% triangle fill, 97.0% vertex fill, 31.8% valid cones, 8,995 hierarchy nodes. Cone-0.25: 86,219 / 70.3% / 96.5% / 33.7% / 9,011. Cone-0.50: 86,285 / 70.2% / 96.5% / 35.6% / 9,025. Offline-only 64/126: 63,556 / 48.4% / 96.9% / 23.1% / 7,471 and was marked runtime-incompatible. Cone-0.50 was the sole GPU candidate because it produced the strongest cone-validity gain at a small count cost.
- Matched 1920x1080 Bistro Presentation/DDGI High capture (120 warmup, 60 measured): Forward average 12.251 -> 12.209 ms (-0.34%), p95 12.439 -> 12.556 ms (+0.94%); submitted opaque meshlets 83,475 -> 83,725; emitted 44,176 -> 44,243; valid cone tests 10,996 -> 12,373 and cone rejects 429 -> 473; all compaction overflows remained zero. This is not a clear Forward win.
- Whole-frame average/p95 changed 26.533/28.056 -> 28.780/42.616 ms because `AmbientOcclusionPass` alone spiked from 4.429/4.479 to 6.773/21.712 ms while Forward stayed flat. HDR passed (relative RMSE 0.0928, FLIP p95 0.00848). Per the requested retain-and-record policy, the cone-0.50 cooked candidate remains in the local outputs for the final decision, but the source-controlled global production profile was not promoted.
- Sponza source audit: the Curtains glTF explicitly marks `metal_door` two-sided; its 16 primitives contain 101,456 triangles, 29,560 boundary edges, zero non-manifold edges, and zero degenerate triangles, so all are open topology. The existing healthy stationary Sponza visual capture supports retaining the authored flag; no source allowlist/material edit or recook was made.

## Plan 9 — shared temporal surface-validity producer

- Added a versioned four-word-per-pixel codec and lazy, double-buffered full-resolution resource. Motion-vector opaque, masked, authored-foliage, and grass paths publish stable identity, current/previous-pose view depth, and a geometric octahedral normal. The compute producer conservatively validates the documented floor/floor, ceil/floor, floor/ceil, and ceil/ceil reprojection taps.
- Render-graph ownership orders current-bank motion writes before the producer and carries the previous bank as history. Camera/scene/history resets fail closed, identity zero is invalid, and the producer remains unavailable without an admitted shared consumer. The existing feature-local histories are unchanged.
- At 1920x1080 the two 16-byte-per-pixel banks allocate 63.28 MiB. The dormant baseline allocated none of it; Plan 12 supplies the first consumer and the matched measurement below therefore captures both allocation-side writes and producer execution.
- Five affected shaders compiled, the two compute modules passed Vulkan 1.3 `spirv-val`, focused shared codec/tap/graph contracts passed, and the Release application build passed with zero warnings or errors.

## Plan 12 — directional-shadow shared-validity prefilter

- Directional temporal filtering now dispatches the shared producer on the render-graph-selected queue and tests the mask bit corresponding to its existing nearest history texel before loading the three local history words. The 12-byte shadow history, exact receiver identity, stricter local depth/normal checks, blocker handling, age, neighborhood clamp, blend, diagnostics, and reset rules remain. Allocation failure or incompatible extent selects the complete legacy local-validation path.
- Kept the directional temporal push ABI at the portable 128-byte limit by packing shared availability into its existing internal temporal flags and deriving the shared frame bank from the existing history index. Focused shared/directional shader contracts passed 11/11.
- Matched 1920x1080 Bistro Presentation/DDGI High stress captures (60 warmup, 30 measured): MotionVector 1.157 -> 1.876 ms (+0.718 ms, +62.1%); producer plus `DirectionalShadowTemporalPass` 0.703 -> 1.043 ms (+0.340 ms, +48.4%); affected aggregate 1.861 -> 2.919 ms (+1.058 ms, +56.9%). GPU frame average 35.396 -> 36.469 ms (+1.074 ms, +3.0%), p95 36.750 -> 38.011 ms (+3.4%). ForwardPlus and AO were flat, making the added full-resolution bandwidth the likely cause.
- HDR passed (relative RMSE 0.0443, FLIP p95 0.00603). This is a measurable regression and does not satisfy the plan's original net-gain retention gate, but it is retained and explicitly recorded under the requested final-decision policy because the whole-frame regression is not severe enough to invoke the user's emergency-revert exception.

## Plan 4 — compact common-surface feasibility

- Implemented Gate 1 only. Two counters were appended to the existing fence-complete receiver-cache diagnostic ABI: surviving strict-`SimpleOpaque` pixels and the subset eligible for a shared material payload. Writes exist only in dedicated qualification mesh/fragment artifacts; production Forward programs retain their prior interfaces and atomic counts.
- Eligibility fails closed unless the material has only constant default-texture bindings, identity texture transforms and primary UVs, no extension flags/data, opaque coverage, and zero emissive output. The diagnostic mesh stage additionally rejects skinning and LOD-dither transitions. The existing scene classifier routes vertex-color, normal-map, masked, transformed-UV, and alternate-UV geometry to `SimpleFullInput`, outside the eligible family.
- A 1920x1080 Bistro Presentation/DDGI High qualification capture reached SurfaceAware mode with valid counter readback. The resolver reported `requested=CompactedSimpleFullInput, effective=CompactedSimpleFullInput`; no strict `Simple` family was selected. The umbrella scene telemetry contained 83,725 simple-or-simple-normal meshlets and zero full-material meshlets, while the strict counters measured 0 candidate and 0 eligible pixels. Eligible frame coverage is therefore zero for this representative workload.
- The capture exhausted its unrelated DDGI settling allowance and its disturbed GPU time is not treated as performance evidence. This does not affect the fence-complete coverage result; validation warning/error counts were both zero. Evidence: [qualification capture](../../.perf-loop-runs/common-surface-plan4-routing-trace2-20260905/coverage.json).
- Per the plan's first stop gate, no `RG32_UINT` material target, producer bandwidth, or consumer migration was added. A full-resolution payload cannot benefit this workload when none of its pixels satisfy the required contract.
