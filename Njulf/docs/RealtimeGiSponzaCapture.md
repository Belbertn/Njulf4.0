# Realtime GI Sponza capture contract

`SampleSponzaGiCaptureContract` is the single in-repo capture contract for the 2026-07-16 Sponza GI transport/support regression. It runs the canonical `GiSponzaRightWallStationary` profile at `1600x900`, locks deterministic validation settings, warms the low bookmark for 2048 frames, settles the high bookmark for another 2688 frames, captures both named endpoints, and traverses the 9 m vertical path in 16 seconds at 60 fixed frames per second. The canonical profile deliberately contains no authored DDGI volumes; Sponza exercises the generic `DdgiHigh` camera-relative rings.

Cornell is only a diagnostic control in this workflow: its scene owns an authored DDGI volume, while Sponza does not. Sponza does author two local reflection probes, but those volumes belong to the specular-reflection system and must not be treated as DDGI coverage. The Sponza presentation profile admits their generic capture/prefilter producer with a bounded per-frame budget so shaded stone and curtains receive local reflections instead of falling back to the unobstructed procedural sky.

The contract is intentionally receiver-centric. Its central upper façade, right upper wall, left and right gallery interiors, central arcade interior, and outdoor reference ROIs are world-space AABBs and are sent to the Simple-DDGI CPU coverage oracle at every one of the 960 fixed vertical-path frames. Each receiver must remain covered by the generic near or mid ring (at most `3.75 m` spacing), and every actual ring-edge transition must have a coarser fallback. The local-volume contributor output is expected to be empty unless a developer explicitly adds a standalone authored volume for an A/B test.

Use `--sponza-gi-capture-dir <directory>` for scripted captures. It is deliberately incompatible with smoke-frame options and baseline one-frame export because it owns its complete deterministic sequence. Storage qualification may additionally name `--simple-ddgi-storage-mode` and `--simple-ddgi-mirror-coverage`; the capture reapplies those representation-only overrides after locking the scenario and records both resolved modes in the run manifest, preventing a requested A/B variant from silently reverting to preset defaults. The run emits its contract fingerprint, hash-addressed artifact index, coverage-oracle sidecar, visual-metric-gate sidecar, two performance snapshots, and the locked outputs per endpoint. In addition to beauty/direct and the existing ownership/support views, it records `DdgiGatherClipmap`, `DdgiGatherBlendWeight`, `DdgiGatherFallback`, `DdgiSampledIrradiance`, `DdgiFinalDiffuse`, `DdgiProbeIndex`, `DdgiRayBudget`, and `FinalIndirect`. The obsolete receiver `DdgiUpdateReasons` and `DdgiClassificationInvalidScore` outputs are not advertised because the compact Simple-DDGI receiver payload does not publish those values; scheduler reasons remain available in the probe overlay. Its direct-only output disables DDGI plus diffuse/specular environment surface lighting while retaining the sky background, so beauty-minus-direct isolates indirect transport instead of comparing against unowned diffuse IBL. It disables particles and animation, reinitializes sample particle seeds, freezes Sponza's astronomical clock so the capture uses the same deterministic presentation sun, and rejects a missing immediate screenshot service or a resolution mismatch rather than mixing output states.

When the sample is launched through RenderDoc, the harness also requests one
present-delimited capture on the first low-bookmark beauty frame after warmup.
The request is a clean no-op when RenderDoc is not injected. Use this command
to retain the resulting `.rdc` beside a display-referred review run:

```powershell
renderdoccmd capture -d <working-directory> -c <capture-template> -w <sample-executable> --sponza-gi-capture-dir <directory> --sponza-gi-capture-mode presentation
```

The in-process request is retired only after a successful present, so the
capture contains the same settled frame as the low-bookmark beauty output.

The source glTF `SUN` is a disabled authoring marker. The startup benchmark applies the same low camera bookmark as the capture, and schema v15 fingerprints the authored loading key, frozen astronomical source, and non-destructive diagnostic ordering so future scene/runtime drift fails before evidence is recorded. The direct-only A/B reference is captured last at each endpoint because disabling GI changes the ray-scene epoch; DDGI views therefore observe the warmed field rather than a three-frame reinitialization transient.

For this closure, validate the transport mechanics before interpreting absolute luminance: visible support and spatial coverage should remain high, ownership/effective weight should approach `1`, fallback should remain near zero, and final/raw receiver energy should not collapse when raw energy is measurable. The simple path's historical `DataConfidence` field is normalized directional-selection support, not data validity, so values around `0.38` are plausible and must not be gated against the old `0.7` target. Sampled irradiance, effective sky visibility, and second-volume contribution remain view-dependent investigation signals rather than fabricated image-pass thresholds; the visual metric gate stays unevaluated until an approved baseline is imported.

Each endpoint output is held for three frames. The first queues the renderer-target request and presents the requested camera/debug state, the second spans the renderer's two-frame timestamp latency, and the third retains that identical state while the client-area screenshot and performance snapshot observe settled output. This is required because the game callback runs before the current Vulkan frame is submitted. `sponza-gi-capture-run.json` cannot become `completed` until every requested `.renderer.png` exists, has a structurally complete PNG stream, and has a recorded SHA-256 and byte count that remains stable across two rendered-frame observations. The capture waits for a bounded 600-frame renderer settlement interval, then writes `failed` if any request remains missing or incomplete. A screenshot request by itself is never capture evidence.

Scripted runs use `ProductionTiming`: detailed investigation counters are disabled and only the non-debug beauty endpoint is timing-eligible. `Ctrl+F11` starts `DetailedDiagnostics`, which enables the detailed GI counters, disables GPU timing collection, and labels its output as diagnostic evidence rather than production performance. `PresentationReview` keeps the production transport at physical unity while restoring Sponza's display-referred ACES/auto-exposure profile for beauty review; diagnostic outputs still use the validation overlay so their values remain interpretable. All three modes write `sponza-gi-visual-metric-gate.json`; it defines deterministic world-space ROI metric requirements but is explicitly `not-evaluated-no-approved-baseline` until reviewed reference images and thresholds are imported. No visual baseline or threshold is fabricated by the harness.

Original source baseline files are tracked separately in [the baseline manifest](../Plans/Baselines/RealtimeGiClosure-20260715/manifest.json). They remain pending external import until the supplied attachment files and their SHA-256 values are available.
